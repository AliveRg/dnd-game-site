# Как выпускаются изменения сайта

Общий репозиторий команды — `AliveRg/dnd-game-site`. В клоне команды `origin` указывает на него. Исходный `rogovekartem-cpu/dnd-game-site` доступен как `upstream` для сравнения и переноса выбранных работ. Приглашение принимает пользователь GitHub. Новые коммиты в исходном репозитории попадают в общий репозиторий только при явном переносе.

| Ветка | Назначение |
|---|---|
| `main` | Публичный сайт dungeons-bgd.ru. Владелец проверяет изменения перед выпуском. Timeweb собирает эту ветку. |
| `design/rogovik` | Постоянная рабочая ветка дизайнера. Дизайн исходной версии, галерея, формы, генератор персонажа, карта и календарь. |
| `codex/timeweb-deploy` | Ранее развёрнутый код. Исходная точка перехода на main — 3305b06. |

## Как вы будете работать дальше

Допустим, Роговик переделал карточки миров, а вы хотите выпустить только карточки. Он делает оформление отдельным коммитом в `design/rogovik`. Для выпуска вы создаёте короткую ветку от `main`, переносите туда этот коммит, проверяете карточки с актуальными данными и открываете pull request в `main`. После вашего одобрения и слияния Timeweb публикует изменение. Старые формы, калькулятор и остальные эксперименты продолжают жить в ветке дизайна до тех пор, пока вы сами не решите их выпустить.

### Дизайнер

1. После принятия приглашения клонируйте общий репозиторий. В существующем клоне проверьте адрес `origin`.
2. В чистом рабочем дереве выполните `git fetch origin`, `git switch design/rogovik`, `git pull --ff-only origin design/rogovik`.
3. Оформляйте каждую самостоятельно выпускаемую задачу отдельным коммитом. Включите её стили, изображения и необходимые импорты. Проверьте на телефоне и на компьютере.
4. Выполните `git push origin design/rogovik`. Передайте владельцу SHA, перечень зависимостей и способ проверки результата.

### Владелец

Пример для одного коммита. Вместо SHA подставьте хеш, который передал дизайнер.

```bash
git fetch origin
git switch -c release/world-cards origin/main
git show --stat SHA
git cherry-pick -x SHA
npm ci
npm run build
git diff --stat origin/main...HEAD
git push -u origin release/world-cards
gh pr create --base main --head release/world-cards
```

Если компонент в main использует другие поля или маршруты, разрешите конфликт с учётом действующего API и выполните `git cherry-pick --continue`. Если исходный коммит смешивает несколько задач, отмените незавершённый перенос командой `git cherry-pick --abort` и перенесите выбранную правку вручную. Укажите исходный SHA в PR. Перед слиянием проверьте список и страницу мира, переходы, мобильную ширину и отсутствие посторонних изменений в PR.

После слияния сопоставьте SHA в GitHub и деплое Timeweb, проверьте `/api/health`, `/api/ready` и затронутые страницы. При сбое выберите предыдущий успешный деплой и восстановите нужный код через revert в отдельном PR. Откат версии приложения сам по себе не откатывает миграции базы.

## Среда разработки

Используйте Node 24, параметры из `.env.example`, локальную PostgreSQL и тестовое хранилище для работы с файлами. Для локальной разработки задайте `NUXT_PUBLIC_YANDEX_METRIKA_ID=0` и `NUXT_PUBLIC_INDEXABLE=false`. Ключи, рабочие пароли и файлы окружения хранятся отдельно от Git. Для тестов заявок используйте вымышленные данные. Выберите свой промпт в [инструкции для Claude Code](prompts/claude-design.md) или в [плане владельца](prompts/release-assistant.md).
