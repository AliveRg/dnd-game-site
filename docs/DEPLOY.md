# Деплой на Timeweb Cloud App Platform

Схема: **GitHub → App Platform (Dockerfile) → контейнер Node на порту 3000 → Timeweb сам вешает nginx + SSL на 80/443**.
Открывать порты и ставить сертификат руками не нужно — это делает платформа. SSH/root-пароль для App Platform **не нужен** (это не VPS), не пересылай его в чатах.

## 1. Репозиторий

```bash
cd "~/vs code/dnd game site"
git init -b main
git add .
git commit -m "init: nuxt + docker"
git remote add origin git@github.com:<you>/<repo>.git
git push -u origin main
```

`.env` в git не попадает (`.gitignore`). Все секреты — только в переменных App Platform.

## 2. Создание приложения

App Platform → **Создать** → тип **Docker** → подключить GitHub → репозиторий.

| Поле | Значение |
|---|---|
| Ветка | `main` |
| Коммит | Сборка по последнему коммиту |
| Автодеплой | **Включить** (каждый push в main = обновление сайта) |
| Фреймворк | **Dockerfile** (не Vue! панель увидит package.json и предложит Vue — игнорируем) |
| Путь до директории проекта | `/` (корень). **Не** `/Dockerfile` — это была ошибка в старом проекте |
| Путь проверки состояния | `/api/health` |
| Регион | тот же, что у БД (для приватной сети) |

Порт платформа берёт из `EXPOSE 3000` в Dockerfile.

## 5. Домен и SSL

Домена пока нет — сайт работает на техническом адресе Timeweb и закрыт от индексации (`NUXT_PUBLIC_INDEXABLE=false`). Когда купят домен:

1. App Platform → приложение → **Домены** → добавить `домен.ru` и `www.домен.ru`.
2. У регистратора: A-запись (или CNAME) на адрес, который покажет панель.
3. SSL Let's Encrypt платформа выпустит сама после того, как DNS обновится (обычно до нескольких часов).
4. Включить редирект www → без www (или наоборот) — один вариант должен быть главным для SEO.
5. Поменять `NUXT_PUBLIC_SITE_URL` на домен и `NUXT_PUBLIC_INDEXABLE=true` → передеплой.

## 6. Яндекс Метрика + Вебмастер

1. metrika.yandex.ru → новый счётчик → домен. Включить Вебвизор. Номер — в `NUXT_PUBLIC_YANDEX_METRIKA_ID`.
2. Цели (тип «JavaScript-событие»): `booking_sent` (заявка из календаря), `hero_form_sent` (форма на первом экране).
3. webmaster.yandex.ru → добавить сайт → подтвердить → «Файлы Sitemap» → `https://домен.ru/sitemap.xml`. Регион сайта → город клуба.
4. Яндекс Бизнес: карточка организации с адресом — сильно помогает локальному SEO и картам.

## 7. Почта

Яндекс 360: Настройки → Безопасность → **Пароли приложений** → «Почта» → этот пароль в `NUXT_SMTP_PASS`.
Проверка: отправить тестовую заявку с сайта → письмо на `NUXT_MAIL_TO` + запись в `/dragons`.

## Проверки после запуска (обновлено 15.11.2026)

- `/api/health` — liveness процесса, HTTP 200 `{ "ok": true }`, используется Docker и App Platform. Не проверяет БД.
- `/api/ready` — готовность PostgreSQL: HTTP 200 при рабочей БД, HTTP 503 с `db=unconfigured` или `unavailable` при проблеме. Не назначать его контейнерной проверкой, если публичный сайт должен оставаться доступным при отказе БД.
- Успешный healthcheck не означает, что формы/админка готовы. Без `NUXT_DATABASE_URL` они не работают; API заявок продолжает возвращать ошибку вместо фиктивного успеха.

В App Platform → приложение → Настройки → Переменные окружения перенесите значения из локального `.env.timeweb` (он исключён из Git). Обязательны NUXT_DATABASE_URL, NUXT_DB_SSL=true, NUXT_ADMIN_LOGIN, NUXT_ADMIN_PASSWORD, NUXT_SESSION_PASSWORD; для изображений также NUXT_S3_ENDPOINT, NUXT_S3_REGION, NUXT_S3_BUCKET, NUXT_S3_ACCESS_KEY, NUXT_S3_SECRET_KEY. Не вставляйте строки с комментариями; при ручном вводе отдельных значений убирайте внешние кавычки JSON. После сохранения переменных нужен новый деплой.

Наличие локального файла `.env.timeweb` не передаёт переменные в Timeweb автоматически. Docker намеренно не копирует секретные env-файлы. Не добавляйте их в репозиторий.

## Invalid URL при входе и пустая карта

Ошибка `ERR_INVALID_URL` в `pg-connection-string` означает, что значение NUXT_DATABASE_URL не является корректным PostgreSQL URL. Это происходит до соединения с БД и не означает неверный пароль админки. Код принимает внешние парные кавычки и скопированный префикс NUXT_DATABASE_URL=; если строка всё равно некорректна, возвращает безопасный HTTP 503 без исходного значения.

Для ручного заполнения полей панели используйте локальный игнорируемый файл `.env.timeweb.panel`: значение справа от `=`, без имени переменной и без внешних кавычек. Пароль в URL должен быть percent-encoded, в частности # → %23, | → %7C, + → %2B. Не заменяйте строку подключения паролем админки. После сохранения переменных сделайте новый деплой.

Исходные 13 сюжетов и карта миров сохранены без изменений относительно main. При холодном запуске с недоступной БД публичный каталог берёт исходные сюжеты; при наличии успешного ответа БД используется он, включая скрытые/удалённые записи. Формы и админка не используют этот резервный режим: для них требуется рабочая БД.

Метатег Яндекс Вебмастера: `yandex-verification=4b93841bf1a2d148`, находится в head HTML.

Если панель сохраняет в NUXT_DATABASE_URL исходные символы пароля (#, |, <, +), сервер нормализует пароль в части между user: и @host до создания pg.Pool. Уже кодированные пароли повторно не кодируются. Фрагменты после имени БД, многострочные значения и некорректные URL по-прежнему отклоняются. Для пароля с буквальным / используйте percent-encoding.
